📱 ft_hangouts — Android Messenger App
Project Overview: A native Android SMS messenger built with Kotlin, Jetpack Compose, and SQLite for 42 School.

📌 Project Summary
ft_hangouts is a functional Android messaging application (similar to WhatsApp) that enables users to manage contacts and communicate via SMS. The app features local database storage, multi-language support, custom theme settings, and lifecycle tracking.

🚀 Requirements & Capabilities
Core Features
👤 Contact Management: Create, Edit, and Delete contacts with up to 5 details (Name, Phone Number, Email, Address, Notes).

💬 Messaging System: Send and receive real-time text messages (SMS) using native Android APIs.

🗃️ Database Integration: Local persistent storage for contacts and chat history using SQLite via custom DAOs.

🏡 Homepage / Main Screen: Chat overview displaying recent conversations sorted chronologically by the latest message.

💬 Conversation History: Clear, visually separated chat bubbles distinguishing between sent and received messages.

🌐 Multi-Language Support: Instant switching between 2 system languages (e.g., German / English).

⏱️ Background Lifecycle Tracker: Displays a notification or toast with the exact time the app spent in the background when returning to the foreground.

🎨 Custom Header Color: Dynamic app theme customization via Settings.

📱 Orientation Support: Native layout compatibility for both Portrait and Landscape modes.

🖼️ 42 App Icon: Customized application launcher icon featuring the 42 logo.

Bonus Features Included
📸 Contact Avatars: Support for contact profile pictures (stored and rendered as Bitmaps).

📞 Direct Calling: One-click option to make phone calls directly from the contact screen.

✨ Material Design 3: Modern, clean, and responsive UI built entirely with Jetpack Compose.

📁 Project Structure & File Architecture
Core System & Configuration Files
🛠️ build.gradle.kts (Generated by Android Studio, heavily modified)

Defined at the root of the app module. It configures the build setup, target Android SDK versions, Kotlin compiler options, and external dependencies (such as Jetpack Compose, Material3, and Navigation components).

📜 AndroidManifest.xml (Generated by Android Studio, modified)

Located in src/main/. It acts as the blueprint for the Android OS. It declares app components (Activities, BroadcastReceivers), configures app permissions (RECEIVE_SMS, SEND_SMS, READ_SMS, CALL_PHONE), and registers the SmsReceiver with high intent filter priorities.

🚀 MainActivity.kt (Generated entry point, modified)

The main entry point of the application. It initializes the app lifecycle observers, handles runtime SMS/Call permission requests, restores saved user preferences (Language & Header Color), and hosts the root Jetpack Compose Navigation graph.

📡 SmsReceiver.kt (Custom File)

A custom BroadcastReceiver that catches incoming SMS intents (android.provider.Telephony.SMS_RECEIVED). It automatically identifies the sender, matches them against existing contacts in the SQLite database, and persists the incoming message seamlessly.

🗄️ Database Layer (db/)
The database layer manages persistent data storage without external ORM libraries, utilizing raw SQLite helpers and Data Access Objects (DAOs):

Contact.kt & Message.kt: Kotlin data models defining the schemas for contacts and messages.

DatabaseHelper.kt: Extends SQLiteOpenHelper to handle database creation, table schemas, and database versioning.

ContactDao.kt: Provides helper methods for SQLite operations on contacts (CRUD, searching contacts by phone number, etc.).

MessageDao.kt: Provides queries to fetch, insert, and retrieve conversation history or the latest message for each contact.

🖥️ UI Screens (ui/screens/)
The user interface is fully declarative, built with Jetpack Compose:

🏠 Start_Screen.kt: The landing screen offering quick navigation buttons to the Main Screen, Contact List, or Settings.

💬 Main_Screen.kt: The homepage. Displays a list of all active conversations sorted descending by the timestamp of the latest message. Includes an interactive NewChatButton to start a chat via a contact picker or by creating a new contact.

📜 ContactList_Screen.kt: Displays all stored contacts with their phone numbers and details. Allows instant creation of new contacts via dialogs.

👤 Contact_Screen.kt: Detailed view for a single contact. Provides options to Edit, Delete, or initiate a direct Call/Chat.

✉️ Chat_Screen.kt: The main conversation interface. Displays chronologically ordered chat bubbles, auto-scrolls to the newest message, and uses SmsManager to send real-time SMS.

⚙️ Settings_Screen.kt: Controls app-wide configurations including dynamic Header/Theme color selection and active Language toggles.

🧩 AppScreens.kt & AppScreensRouter.kt: Defines navigation routes, screen states, and argument passing between views.

🛠️ Helper Functions (ui/helpfunctions/)
Modularized components built to keep screen files clean and maintainable:

🛡️ ContactCheck.kt: Input validation logic for creating/editing contacts (e.g., verifying phone number formats and non-empty name fields).

📝 ContactForm.kt: A reusable form dialog component with text fields for entering or editing contact details.

🖼️ ContactImages.kt: Handles decoding, rendering, and fallback logic for contact profile pictures using Bitmaps and ImageDecoder.

🔘 NavigationsButtons.kt: Reusable UI components for standard navigation actions used consistently across multiple screens.

🎨 Theme & Styling (ui/theme/)
Color.kt, Theme.kt, Type.kt: Configures Material Design 3 color palettes, typography, and dynamic header/theme color application based on user preferences stored in the app settings.
